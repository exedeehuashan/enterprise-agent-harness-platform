# EAHP 用户手册

EAHP（Enterprise Agent Harness Platform）是一个让 AI 智能体在受控、可审计的方式下干活的平台。方案 4（AI 质量工程）是建在它上面的第一个业务模块：自动跑测试、分析失败、管理发布门禁，并可以让 Claude Code 修复失败的测试。

控制台地址：<http://127.0.0.1:8088>。右上角（登录页右上角也有）的 **中文 / English** 按钮切换语言，选择会记在当前浏览器里。

## 1. 登录和角色

用管理员发给你的 **API 令牌**登录。令牌只保存在当前浏览器标签页里，关掉标签页就要重新登录。

| 角色 | 能做什么 |
| --- | --- |
| 查看者（VIEWER） | 查看任务、运行、测试结果、质量看板 |
| 操作员（OPERATOR） | 另外还能创建任务、发起运行、取消运行、请求自动修复 |
| 审批人（APPROVER） | 另外还能审批、管理项目和策略、隔离测试、配置通知和代码智能体 |

命名令牌由管理员在 **管理 → API 令牌** 中签发，签发时只显示一次。

## 2. 任务和运行

- **任务**页面列出所有任务。点 **新建任务**，填写标题和描述。
- 在任务详情页可以：
  - **运行测试套件**：选择项目、套件、分支或提交，然后开始运行；
  - **运行 API 测试**：选择测试集和环境；
  - **代码智能体**：写修改要求，让 Claude Code 改代码（需要审批）；
  - **请求计划**：让模型拆出几个步骤，校验后可以执行。
- 每次运行都有自己的页面，显示：
  - 状态和结果；
  - 测试摘要和失败的测试（附历史：新失败、已在失败、不稳定）；
  - 产物下载和审计记录。
- 失败的运行可以点 **用 AI 分析**。模型会根据证据给出可能原因、类别和下一步建议。分析结果只作参考，不会自动执行任何操作。

## 3. 审批

需要访问主机 Docker 的运行、代码智能体、临时环境等操作，都需要审批人批准。审批页面列出等待处理的运行。批准时会绑定这次运行的**输入摘要**，也就是说，批准的就是你看到的那个提交和那组参数，之后的任何改动都会让批准失效。

## 4. 测试项目

**测试项目**页面显示每个被测项目：

- **套件和策略**：允许的镜像、能否访问 Docker、能否访问外网、最长时间。项目还可以在仓库里的 `.eahp/qa-suites.json` 声明更多套件，但必须遵守这里的策略。
- **计划**：分支有新提交时运行，或者按 Cron 定时运行。
- **环境**：已部署的被测系统地址（例如 UAT），供 API 测试和性能测试使用。
- **按提交的临时环境**：用仓库自己的 compose 文件，为某个提交单独启动一套系统：
  - **在新环境上运行测试**：跑完 API 测试后自动销毁环境；
  - **启动环境**：环境保留到有效期结束，期间可以拿它跑其他测试，也可以手动 **停止**。
- **GitHub 回写**：开启后，测试结果会以提交状态和一条评论的形式写到 PR 上。
- **AI 生成的 API 测试**：根据仓库里的 OpenAPI 文件生成测试草稿，可以直接运行，也可以下载后提交到仓库。

## 5. PR

**PR** 页面显示 EAHP 从 GitHub 发现的 PR，以及每个新提交触发的运行：

- 运行范围：完整运行，或只运行受影响的模块；
- 跳过的原因：例如来自 fork，或改动不影响这个套件；
- **影响分析**：改了哪些文件，影响哪些模块和测试类。

## 6. 质量

**质量**页面是发布前的总览：

- **通过率、失败测试、不稳定测试、最慢的测试**：可以选择最近 7 到 90 天。
- **发布门禁**：输入分支或提交，查看 PASS / FAIL / PENDING 和原因。门禁可以要求：
  - 指定的套件全部通过；
  - 行覆盖率不低于某个值；
  - **新代码覆盖率**不低于某个值，即这次改动的代码行有多少被测试覆盖；
  - **性能**达标：p95 延迟、错误率，以及相对最近运行的变慢幅度。
- **QA 报告**：生成 Markdown 报告，可以复制到 PR 或邮件里。
- **对比提交**：两个提交之间新增的失败、修复的测试、新增和删除的测试。
- **覆盖率**：覆盖率随时间的趋势。还可以检查两个提交之间改动的行有没有被覆盖，并列出未覆盖的行号。
- **性能**：每次 k6 测试的 p95 趋势，图上会标出门禁限制。
- **被隔离的测试**：审批人可以把已知不稳定的测试隔离一段时间（最长 30 天），隔离期间它的失败不阻断门禁。**EAHP 建议**一栏会列出平台根据证据（同一提交上既通过又失败）发现的不稳定测试，审批人可以一键确认隔离 14 天，或者驳回。
- **自动修复**：见下一节。

## 7. 让代码智能体修复失败的测试

1. 打开一次失败的套件运行，点 **用代码智能体修复**。
2. 审批人批准代码智能体的运行。
3. Claude Code 在隔离的容器里修改代码。它只能访问 Anthropic API 和 Maven、npm 仓库。
4. EAHP 推一个新分支，开一个**草稿 PR**。
5. EAHP 在 PR 的提交上重新跑同一个套件，把结论写到 PR 评论里：**已修复**、**部分修复**或**未修复**。
6. 由人审阅草稿 PR 并决定是否合并。EAHP 从不自动合并。

项目还可以开启"对每次失败的运行提出修复"。这时平台会自动发起修复请求，但每个请求仍然需要审批人批准，每个项目每天最多 3 个。

只有代码缺陷类的失败（断言失败、意外异常、编译错误、超时）会交给代码智能体。环境问题，比如没有 Docker、网络不通，会被拒绝，因为改代码只会掩盖这类问题。

## 8. 管理（审批人）

- **AI 模型**：当前使用的模型和今天的用量。
- **AI 评测**：用 12 个固定用例检查 AI 功能的质量，会消耗真实的 token。
- **业务模块**：可以整体关闭某个业务模块，例如方案 4。
- **存储和保留**：产物 30 天后过期（只删除内容，保留元数据），每晚清理。
- **备份恢复演练**：每晚自动演练一次，也可以点 **立即演练**。
- **通知**：把事件发到 Webhook、钉钉、企业微信、飞书、Slack 或邮件。添加后可以点 **发送测试** 确认能否收到。
- **API 令牌**：签发和吊销命名令牌。
- **代码智能体仓库**：登记允许代码智能体修改的仓库，并设置是否允许推送分支。
- 测试项目页面的 **管理** 区域：登记项目，修改策略、PR 触发器、发布门禁和套件，所有改动都有记录。

## 9. 常见问题

| 现象 | 原因和处理 |
| --- | --- |
| 运行一直是"等待审批" | 需要审批人在 **审批** 页面批准。 |
| `RUNNER_UNAVAILABLE` | 后端无法访问 Docker。请运维用 `EAHP_QA_RUNNER=on` 部署。 |
| 测试失败，类别是"环境 / Docker" | 测试需要 Docker（Testcontainers），但运行环境没有 Docker。这不是代码问题。 |
| `CODE_AGENT_NOT_CONFIGURED` | 没有配置 `ANTHROPIC_API_KEY`。 |
| `PUSH_FAILED` | GitHub 写权限 token 没有该仓库的 Contents 写权限。改动和日志仍然保留在运行的产物里。 |
| AI 分析返回模型错误 | 检查 AI 模型的配置和当日 token 预算（管理 → AI 模型）。 |
