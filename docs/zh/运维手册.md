# EAHP 运维手册

本手册面向负责部署和维护 EAHP 的运维人员。所有命令都在仓库根目录执行。

## 1. 环境要求

- Docker（含 Compose v2）、curl、openssl。
- 如果要运行 QA 测试（方案 4），后端需要访问 Docker。这相当于主机级权限，只应在**专门用于 EAHP 的机器**上开启。
- 端口只绑定在本机：
  - 控制台：`127.0.0.1:8088`
  - API：`127.0.0.1:8080`
  - PostgreSQL：`127.0.0.1:5432`

  如果要远程访问，请在前面加 TLS 反向代理。

## 2. 首次部署

```bash
cp .env.example .env && chmod 600 .env
```

编辑 `.env`，至少设置以下几项：

| 变量 | 说明 |
| --- | --- |
| `DB_PASSWORD` | 数据库密码 |
| `EAHP_SECURITY_ADMIN_TOKEN` | 审批人令牌，32–256 位随机 URL 安全字符 |
| `EAHP_SECURITY_OPERATOR_TOKEN` | 操作员令牌（可选） |
| `EAHP_SECURITY_VIEWER_TOKEN` | 查看者令牌（可选） |
| `EAHP_QA_RUNNER=on` | 允许运行 QA 测试容器 |
| `DOCKER_SOCKET_GID` | Docker socket 在容器里看到的组 ID；Docker Desktop 上是 0 |

生成随机令牌的方法：

```bash
openssl rand -base64 48 | tr -d '/+=' | cut -c1-48
```

然后部署：

```bash
scripts/deploy.sh
```

部署脚本依次执行：校验配置 → 备份数据库（如果已经在运行）→ 构建镜像 → 启动并等待健康检查通过 → 通过控制台代理做冒烟测试。看到 `OK: console http://127.0.0.1:8088 ...` 就表示成功。

`.env`、`backups/` 里的备份和导出文件都不要提交到 git，权限保持 600 / 700。

## 3. 可选功能的配置

全部在 `.env` 里设置，改完后执行 `scripts/deploy.sh`。

| 功能 | 变量 |
| --- | --- |
| AI 模型（Claude） | `EAHP_AI_PROVIDER=anthropic`、`ANTHROPIC_API_KEY`、`ANTHROPIC_MODEL`（默认 claude-opus-5-5）、`ANTHROPIC_EFFORT` |
| AI 模型（DeepSeek） | `EAHP_AI_PROVIDER=deepseek`、`DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL` |
| AI 每日 token 上限 | `EAHP_AI_DAILY_TOKEN_BUDGET`（默认 500000） |
| 代码智能体 | 同一个 `ANTHROPIC_API_KEY`。先执行一次 `scripts/build-code-agent.sh` 构建运行镜像 |
| 代码智能体出网 | `EAHP_CODE_AGENT_NETWORK=proxy`（默认，只允许白名单主机）；白名单用 `EAHP_CODE_AGENT_EGRESS_ALLOW` 配置 |
| GitHub 轮询 PR | `EAHP_GITHUB_POLL_ENABLED=true`、`EAHP_GITHUB_TOKEN`（只读） |
| GitHub 回写和开 PR | `EAHP_GITHUB_WRITE_TOKEN`（fine-grained token，只选被测仓库；Contents、Pull requests、Commit statuses 设为读写） |
| 控制台链接 | `EAHP_PUBLIC_URL`，用在 GitHub 状态和通知的链接里 |
| 邮件通知 | `EAHP_SMTP_HOST`、`EAHP_SMTP_PORT`、`EAHP_SMTP_USERNAME`、`EAHP_SMTP_PASSWORD`、`EAHP_SMTP_FROM`、`EAHP_SMTP_STARTTLS` |
| 备份恢复演练 | `EAHP_BACKUP_DRILL_ENABLED=true`（默认），每晚 04:15 UTC |

**单点登录（SSO）**：

- 本地开发：先执行 `scripts/sso-dev.sh`。它会生成 Keycloak 的 realm 和测试用户（alice 是审批人，bob 是操作员，carol 是查看者），随机密码保存在 `sso/generated/dev-users.txt`。然后执行 `EAHP_SSO=on scripts/deploy.sh`。
- 从手机或其他设备通过 Tailscale 登录（本地 Keycloak）：
  1. 把控制台和 Keycloak 都发布到 tailnet（只在你的 Tailscale 网络内可访问）：
     `sudo tailscale serve --bg http://127.0.0.1:8088` 和 `sudo tailscale serve --bg --https=8443 http://127.0.0.1:8180`；
  2. 在 `.env` 设置 `EAHP_SSO_DEV_URL=https://<主机>.<tailnet>.ts.net:8443` 和 `EAHP_CONSOLE_ORIGINS=https://<主机>.<tailnet>.ts.net`；
  3. 执行 `scripts/sso-dev.sh`，重建 Keycloak 容器（`docker compose -f docker-compose.yml -f docker-compose.sso.yml up -d --force-recreate --no-deps keycloak`），再执行 `EAHP_SSO=on scripts/deploy.sh`。
  之后电脑和手机都通过 `:8443` 的地址登录，测试账号密码不变。
- 接入公司的身份提供方：在 `.env` 设置 `EAHP_SSO_ISSUER`、`EAHP_SSO_JWKS_URI`（可选）和 `EAHP_SSO_ORIGIN`，再按 `.env.example` 的说明登记公共客户端 `eahp-console`（重定向地址 `<控制台>/auth/callback`，登出后重定向地址 `<控制台>/`，这样点 **退出** 时也会结束身份提供方的会话），并配置 `eahp-viewer`、`eahp-operator`、`eahp-approver` 三个角色。

钉钉、企业微信、飞书、Slack 机器人不需要改 `.env`，在控制台 **管理 → 通知** 里添加即可。

检查 GitHub token 有没有某个仓库的推送权限（不会推送任何内容，输出 `200` 才表示有）：

```bash
curl -s -o /dev/null -w '%{http_code}\n' -u "x-access-token:$(grep -E '^EAHP_GITHUB_WRITE_TOKEN=' .env | cut -d= -f2-)" 'https://github.com/<owner>/<repo>.git/info/refs?service=git-receive-pack'
```

## 4. 升级和回滚

**升级**：拉取新代码后重新执行：

```bash
scripts/deploy.sh
```

部署前会自动备份数据库。数据库结构由 Flyway 在后端启动时迁移，只会前进。

**回滚**：

1. 切回上一个版本的代码：`git checkout <上一个版本>`。
2. 如果新版本做过数据库迁移，旧代码不认识新结构，需要先恢复升级前的备份，见第 5 节。备份文件名是升级时间，例如 `backups/eahp-20261024T114825Z.dump`。
3. 执行 `scripts/deploy.sh`。

## 5. 备份和恢复

- **自动备份**：每次执行 `scripts/deploy.sh` 时都会备份，文件在 `backups/eahp-<时间>.dump`，默认保留最新 10 个（`EAHP_BACKUP_KEEP`）。
- **手动备份**：执行一次部署脚本即可，或者：

```bash
docker compose exec -T postgres pg_dump -U agent_harness -d agent_harness -Fc > backups/manual-$(date -u +%Y%m%dT%H%M%SZ).dump
```

- **演练**：把备份恢复到一个临时容器里检查，不影响线上：

```bash
scripts/restore.sh --drill
```

  不带参数时检查最新的备份。结果写到 `backups/drill-<时间>.json`；失败时退出码不为 0。

- **正式恢复**：会替换线上数据库。脚本会先做一次安全备份，停掉后端，恢复完再启动：

```bash
scripts/restore.sh --production backups/eahp-<时间>.dump
```

  恢复失败时，脚本会打印恢复安全备份的命令。数据卷不会被删除。

- **平台自动演练**：每晚在一个临时 Postgres 容器里，用线上数据库的最新导出做一次恢复，然后检查结构版本和行数。结果在 **管理 → 备份恢复演练** 和监控指标里。
- **请把 `backups/` 定期复制到另一台机器或存储上。** 演练只能证明备份能恢复，不能防止磁盘损坏。

## 6. 监控

Prometheus 指标地址是 `http://127.0.0.1:8080/actuator/prometheus`，需要任意令牌，请求头为 `Authorization: Bearer ...`。建议告警：

| 指标 | 告警条件 |
| --- | --- |
| `eahp_runs{status="QUEUED"}` 和 `eahp_runs_oldest_queued_seconds` | 队列积压 |
| `eahp_approvals_pending` | 等待审批的运行太多或太久 |
| `eahp_webhooks_failing`、`eahp_webhooks_paused` | 通知投递失败 |
| `eahp_backup_drill_last_failed` | 等于 1 |
| `eahp_backup_drill_last_success_seconds` | 距今超过 2 天 |
| `eahp_qa_results_24h` | 按结果统计的 QA 运行数 |

健康检查：`http://127.0.0.1:8080/actuator/health`（不需要令牌）。

## 7. 日常检查

```bash
docker compose ps                             # 三个容器都应是 healthy
docker logs --since 1h eahp-backend 2>&1 | grep -E "WARN|ERROR" | tail
ls -lt backups | head                         # 最近的备份
```

`docker ps` 里不应长期出现 `eahp-env-*`、`eahp-agent-*`、`eahp-backup-drill-*` 开头的容器：

- `eahp-env-*` 是临时环境，到期后会自动清理。也可以在控制台停止。
- `eahp-agent-*` 网络和 `eahp-backup-drill-*` 容器在每次运行后都会自动删除。

## 8. 安全要点

- 令牌只通过 `Authorization` 请求头传递，不放在 URL 或命令行里。`.env` 的权限保持 600。
- `EAHP_QA_RUNNER=on` 等于把主机级 Docker 权限交给后端。需要 Docker 的套件、临时环境和代码智能体，每次都要审批。
- 代码智能体的容器没有任何 GitHub 凭据，出网只能连白名单主机。推送分支和开 PR 由 EAHP 自己完成，并且只开草稿 PR。
- 临时环境的 compose 文件在启动前会检查：不允许特权模式、绑定挂载、主机网络等，也会去掉端口映射。compose 在空环境变量下运行，读不到 EAHP 的密钥。

## 9. 故障排查

| 现象 | 处理 |
| --- | --- |
| 部署时 `Missing .env` | 按第 2 节创建 `.env`。 |
| 后端启动失败，日志提示令牌无效 | 检查 `EAHP_SECURITY_ADMIN_TOKEN` 的长度（32–256 位）和字符（只能是 URL 安全字符）。 |
| 选了真实模型，但后端启动失败 | 没有填对应的 API key。系统不会静默退回 mock。 |
| QA 运行 `RUNNER_UNAVAILABLE` | 用 `EAHP_QA_RUNNER=on` 部署，并检查 `DOCKER_SOCKET_GID`。 |
| 临时环境 `ENVIRONMENT_POLICY` | compose 文件用了被禁止的设置，例如特权模式或绑定挂载。在运行的 console.log 里能看到原因。 |
| 代码智能体 `CODE_AGENT_EGRESS_UNAVAILABLE` | 后端没有加入运行网络。确认 `EAHP_QA_SELF_CONTAINER=eahp-backend`（docker-compose.yml 已默认设置）。 |
| 代码智能体 `PUSH_FAILED` | token 没有 Contents 写权限，用第 3 节的 curl 命令检查。 |
| 通知显示"失败中" | 在 **管理 → 通知** 查看错误。钉钉、企业微信、飞书返回的错误码会原样显示，例如 `300005: token is not exist`。 |
| 备份演练 `SKIPPED` | 没有开启 QA 运行器，所以没有 Docker 权限。 |
